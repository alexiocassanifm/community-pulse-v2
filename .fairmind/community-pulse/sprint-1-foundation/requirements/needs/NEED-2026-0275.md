# NEED-2026-0275: E1 - Monorepo Foundation & Shared Contracts

**FairMind ID**: 6a15abd0614ab03b81a92995

## Objective
Build the entire pnpm monorepo infrastructure with three workspaces — `apps/api` (Hono backend), `apps/web` (React SPA with Vite), `packages/shared` (Zod schemas and shared TypeScript types) — and guarantee that all validation schemas have a single shared source of truth between frontend and backend.

## Context & Motivation
Production log sweep detected a 94% error rate on `POST /api/submit-preferences`, caused by divergent Zod schemas between client and server in the existing Next.js app. In Next.js App Router there is no mechanism that forces synchronization between form type and route handler validation schema — they can silently diverge with every deploy.

The monorepo with `packages/shared` solves this by construction: a single Zod schema, imported by both the Hono backend and the React frontend. If the schema changes, the TypeScript compiler flags the error everywhere before it reaches production.

## Acceptance Criteria (Epic Level)
- `pnpm build` compiles all three workspaces without TypeScript errors
- Modifying a schema in `packages/shared` causes TypeScript errors in consumer files (automatic enforcement)
- `docker compose up` starts the full dev environment (app + MongoDB)
- `GET /api/health` returns `200 { status: "ok", db: "connected" }`
- Imports from `@community-pulse/shared` work in both `apps/api` and `apps/web`
- CI pipeline green on `main` branch

## Risks
- Path alias configuration in a monorepo may require adjustments to Vite and tsc — plan ½ day spike.
