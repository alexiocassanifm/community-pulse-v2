## User Story

**As an** Administrator, **I want to** initialize the Community Pulse pnpm monorepo with three workspaces (`apps/api`, `apps/web`, `packages/shared`), TypeScript path aliases, and Docker Compose for local development, **so that** the entire development team has a reproducible, consistent local environment and all future packages share a single dependency resolution graph.

## Technical Problem Description

The current Community Pulse application is a Next.js 14 monolith coupled to Supabase. The target architecture requires migrating to:
- `apps/api` — Hono (Node.js) backend
- `apps/web` — React 18 SPA (Vite)
- `packages/shared` — shared Zod schemas + TypeScript types

Without a properly configured monorepo foundation, TypeScript path aliases (`@community-pulse/shared`) won't resolve across workspaces, Docker Compose won't wire the app container to MongoDB, and subsequent epics (auth, public routes, admin routes) have no baseline to build upon.

## Proposed Implementation Approach

### 1. Root workspace configuration
- Create `pnpm-workspace.yaml` declaring packages `['apps/*', 'packages/*']`
- Create root `package.json` with scripts: `build`, `dev`, `lint`, `typecheck`
- Create root `tsconfig.base.json` with strict mode and path aliases:
  - `@community-pulse/shared` → `packages/shared/src`

### 2. Workspace scaffolding
- `packages/shared/package.json` — name: `@community-pulse/shared`, exports `./src/index.ts`
- `apps/api/package.json` — name: `@community-pulse/api`, references `@community-pulse/shared`
- `apps/web/package.json` — name: `@community-pulse/web`, references `@community-pulse/shared`
- Each workspace extends `../../tsconfig.base.json`

### 3. Docker Compose (`docker-compose.yml` at repo root)
```yaml
services:
  app:       # Hono backend + serves React /dist
  mongodb:   # mongo:7 image, port 27017
  mongo-express:  # optional GUI, port 8081
```
- MongoDB data persisted via named volume `mongo_data`
- `app` service depends_on `mongodb` with health check
- `.env.example` documents all required env vars: `MONGO_URI`, `JWT_SECRET`, `PORT`

### 4. Vite path alias alignment
- `apps/web/vite.config.ts` — resolve.alias maps `@community-pulse/shared` to `../../packages/shared/src`
- `apps/api/tsconfig.json` — paths map `@community-pulse/shared` to `../../packages/shared/src`

## Testing Strategy

- **Smoke test**: `pnpm install` completes without hoisting errors
- **Build test**: `pnpm build` compiles all three workspaces with zero TypeScript errors
- **Cross-workspace import test**: Add `import { submissionSchema } from '@community-pulse/shared'` in both `apps/api/src/index.ts` and `apps/web/src/main.tsx` — `pnpm typecheck` must pass
- **Docker test**: `docker compose up` starts all services; `curl http://localhost:3000` responds (even if 404 at this stage)
- **Path alias break test**: Rename an export in `packages/shared/src/index.ts` → confirm TypeScript errors surface in both consumer workspaces
